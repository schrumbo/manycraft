# Users

Provisional archetypes, from the owner's own use. Revise when real user feedback arrives.

| | Archetype | Test with |
|---|---|---|
| A | Alt holder: 2–5 accounts, Windows, mouse, never edited JVM args | mouse only, zero setup, everyday German |
| B | AFK farmer: 10–50 accounts on one server, plays one while the rest idle | status of every account at a glance, swap in one click or key, hidden instances cost nothing |
| C | Operator: several batches with different mods and configs, proxies per account, hundreds of accounts | keyboard and palette, bulk actions, nothing scales worse than linearly |

A is the default user. Nothing may require being C to use the basics; nothing may cap what C can do.

- Adding an account and starting a batch works with zero configuration. Settings refine; they never unlock the core.
- Proxies, JVM args, batch overrides and memory caps appear on first use or opt-in.
- Every command has a mouse path and a palette entry plus shortcut.
- Default paths use everyday German. No "JVM", "Heap", "SOCKS5" on a default path unless the user opened that setting.
- Attention is shown, never shouted: an account that needs work is highlighted in its tile and counted, without modal alerts or sound by default.
- Account tokens never leave the OS keychain in plain text; instance folders the user did not ask to change stay untouched.
- Windows, macOS and Linux count the same.
